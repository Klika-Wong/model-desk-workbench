# 功能入口与操作缺陷核对（2026-11-01）

目前仍是开发预览，**未达到“所有需求都已实现，且都能从 UI 完成”**。本清单覆盖现有桌面主要用户流程及原始需求；不是对服务所有接口的完整验收。源码有接口、按钮可点击、模型执行完成、独立验收通过是不同状态。

## 已复现并修复的操作问题

| 问题 | 原行为 | 修复后的行为 |
|---|---|---|
| 跨项目对话混用 | 更换项目后仍有上一项目的消息、草稿和历史发送选项 | 每项目独立本机记录；切换清空草稿、重置发送范围、丢弃迟到显示结果 |
| 旧版记录归属不明 | 全部对话共用 chat.json | 旧文件保留，不自动分配给任何项目；新记录按规范化项目路径散列保存 |
| 清空结果失真 | 删除错误被吞掉，UI 仍宣布成功 | 真正删除成功才清空画面；失败保留记录并提示 |
| 对话查询中断 | 一次读取失败就解除任务跟踪 | 保留原任务继续查询，不重复派发；慢查询不叠加 |
| 对话无法停止 | 提示可取消却无当前对话任务的取消按钮 | 执行中显示“停止当前任务”；请求成功不冒充执行器已经停止 |
| 已验收被当失败 | accepted 进入失败分支 | 成功显示并保存有效回答；blocked 显示需处理并结束轮询 |
| 搜索入口陈旧 | 新版/原版切换命令无有效目标，新导航缺失 | 增加对话、模型与额度、高级设置，删除失效视图命令 |
| 性能窗口后台读取 | 窗口隐藏仍定时读取，手动刷新可并发 | 可见时每次完成后等待 10 秒；隐藏/关闭停止调度；手动刷新串行 |

切换项目不取消原项目任务。原任务结果仍在其运行记录中，当前桌面对话不自动恢复切走前的任务流；重启后的进行中对话恢复也尚未实现。路径散列用于文件命名，**不是内容加密或操作系统权限隔离**。记录保存失败有提示，未做跨进程文件写入锁。

## 用户流程与 UI 入口

“已有”只表示已接线，不代表本轮完成真实服务端到端验收。离线夹具测试不能替代 WorkBuddy、7B、API 的实际调用。

| 用户能力 | 目前入口 / 实现 | 当前缺口或验收边界 |
|---|---|---|
| 原生桌面窗口、托盘、任务小窗 | Electron 主窗；运行页悬浮窗；托盘 | 已有，安装包、更新与全新电脑仍待验收 |
| 选择项目 | 运行与连接 → 选择项目；对话 → 选择项目 | 已有原生目录选择；跨权限桌面会话仍需实测 |
| 项目对话与可选历史 | 对话 → 读取模型 → 确认 → 发送 | 本轮项目隔离、存储、迟到结果有回归；真实调用待服务恢复 |
| 任务派发、预览、停止 | 运行与连接 → 真实任务；对话停止按钮 | 已有；断网恢复为查原任务，不自动重发 |
| 任务流与详情 | 运行与连接中的任务活动 | 已有任务与验收状态；真实多主导讨论尚未接通 |

| 主题、壁纸、侧栏 | 设置；侧栏布局菜单、拖动分隔条 | 深浅色、静态壁纸、左右停靠已有；视频壁纸未实现 |

## 本轮证据与下一批顺序

- 修复前 Electron 用例实际发现：切换项目仍有 1 条旧消息和旧草稿；迟到回答使新项目画面留有 3 条旧项目消息。修复后这些用例通过。
- `desktop/chat-store.test.cjs`、`chat-ipc.test.cjs`、`chat-prompt.test.cjs`：13 项通过，含实际 IPC 处理器的项目隔离、未打开项目写入拒绝、旧记录保留与删除失败。
- `desktop/async-defects-verify.cjs`：14 项通过，覆盖项目切换、迟到结果、查询恢复、取消、验收状态、清空失败、搜索、性能采样和既有异步回归。21 项既有 UI 检查、65 项桌面冒烟检查通过。
- 本机实际整机采样读到有效内存和 GPU 数据；首次 CPU 等待第二次采样，单模型占用仍未知。夹具里的 12.5% 仅为测试数据，不是用户电脑测量值。
- 本轮工作台服务未运行；WorkBuddy/7B 未实际派发。没有将 CLI 候选就绪当成模型调用成功，没有改用户模型配置。

后续优先完成真实服务验收，再迁移现有连接编辑和执行端设置；之后串起真实主体派发—执行—独立评审—归档流程。记忆实际结构应用、闲时提炼与多组编排分别设计、实现、拒绝用例验收，不能用模式选择器或可点击空壳充数。
